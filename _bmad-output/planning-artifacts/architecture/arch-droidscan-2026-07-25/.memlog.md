- (decision) AD-001: Native Android (Kotlin) chosen as platform. Rationale: TelephonyManager, NetworkStatsManager, Shizuku API access require Android SDK; Kotlin provides null safety, coroutines for async telemetry, and first-class Compose UI support.
- (decision) AD-002: Modular layered architecture with 5 modules: telemetry-collector, knowledge-engine, llm-reasoner, dashboard-ui, and shared-core. Each module has defined boundaries and dependency direction (UI → Reasoner → Knowledge Engine + Telemetry Collector).
- (decision) AD-003: Knowledge engine uses SQLite with sqlite-vss vector extension for on-device corpus storage. ChromaDB considered but adds 15MB+ dependency; sqlite-vss keeps APK lean and leverages Android-native SQLite.
- (decision) AD-004: LLM reasoning via API (GPT-4o-mini / Claude Haiku) for v1.0. On-device model (Gemma 2B / Phi-3-mini) as deferred v1.1 goal. API chosen for: faster iteration on prompt engineering, lower APK size, no model download UX friction. Privacy concern mitigated by: telemetry anonymized before API call, user opt-in required, processing done server-side with no-log承诺.
- (decision) AD-005: UI layer built with Jetpack Compose + a Canvas-based custom renderer for the btop-inspired terminal dashboard. Standard Material 3 components for settings/diagnostic views; Canvas drawText/drawLine for real-time telemetry sparklines and gauge displays.
- (decision) AD-006: Telemetry collection uses Kotlin Flow with a polling interval of 1s for radio metrics, 5s for thermal/CPU. Data emitted via SharedFlow to both the dashboard UI (real-time display) and the anomaly detector (background analysis). No telemetry stored persistently — ephemeral in-memory ring buffer of last 60s for context window.
- (decision) AD-007: Shizuku Power Mode implemented as optional module using Shizuku API (wireless ADB). Detected at runtime; if unavailable, app falls back to Standard Mode gracefully. Power mode unlocks: /proc thermal zone reads, process socket stats, dumpsys radio snippets.
- (decision) AD-008: Tri-Tier resolution engine implemented as a deterministic classifier on LLM output. LLM returns structured JSON (tier, issue_category, steps[], cheat_sheet_text). App-side post-processor validates tier classification, maps Tier-2 to OEM-specific deep link intents, formats Tier-3 cheat sheet. No free-text LLM output displayed directly to user.
